## 背景

用户报告:工作模式 POI 中混有大量高德地图 POI(即本地几百万条杭州 POI 数据)。
这些高德 POI 的公司没有岗位信息,应在主地图(domain)模式展示,工作模式只保留
自己额外找的、带岗位信息的工作 POI。

**用户已定口径(2026-08-19 修正)**:收藏功能**按主地图和工作地图区分**——
不是"工作模式完全不显示收藏",而是 overlay 按当前模式过滤:
- **work 模式**:只显示 `place.mode ∈ {work, internship}` 的收藏(工作模式收藏的公司,
  带岗位);`place.mode === 'domain'` 的地点收藏(无岗位高德 POI)不显示。
- **domain 模式**:只显示 `place.mode === 'domain'` 的收藏(地点);work 收藏不在主地图显示。
- 依据:`SavedPlace` 自带 `mode: MapMode` 与 `kind: 'domain' | 'recruitment'`
  (`server/src/lib/account.ts:63-73`);`saved-overlay.ts:20,23` 已在用 place.mode/place.kind。
- 另加:列表层 kind:'recruitment' 守卫 + mode-cache kind 校验(防缓存污染兜底)。

## 根因(主 Agent 探索定位)

- **主数据流是干净的**:DB work 读路径(`recruitment-store.ts:80-213`)只查 company_sites /
  companies / positions(status='open' + 未过期),**不查 hz_pois**;客户端
  `loadWorkViewport` 用 `isRecruitmentPoi`(kind==='recruitment')+ `withAlivePositions`
  过滤。服务端 work 分支不可能返回 hz_pois。
- **两个真实漏洞**:
  1. **saved-overlay**(`saved-overlay.ts:12-26`):`savedPlaceToOverlayPoi` 构建的
     `DomainPOI` fallback `kind:'domain'`,`category` = 收藏/公司企业;**无岗位**。
     `map-shell.tsx:1109-1112` `mapPois = mergeMapPois(pois, overlayPois, savedOverlay && user)`
     把 overlay 合并进**每个模式**(含 work)的 markers——`savedOverlay` 默认开(map-shell.tsx:231)。
     这些 kind:'domain' pin 出现在工作地图上,点击打开无 JD 的域详情卡。
  2. **mode-cache**(`mode-cache.ts:49-53`):`readModeCache` 用 `isPoi` 只校验
     id/name/location,**不校验 kind**——被污染的 work 缓存(含 domain 行)可被原样还原。
- 列表渲染(marker/卡片)不按 kind 过滤(`runPOIPipeline`/`poiMatchesQuery` 处理两种 kind;
  markers 按 kind 样式但不丢弃)。

## 任务

1. **收藏 overlay 按模式区分**:`map-shell.tsx:1109-1112`(或 savedPlacesToOverlay 调用处)——
   overlay POI 按当前 `mode` 过滤:`canonicalMode(mode)` 是 recruitment(work/internship)时
   只保留 `place.mode ∈ {work, internship}` 的收藏;domain 时只保留 `place.mode === 'domain'`。
   更简单可靠:在 `savedPlacesToOverlay`(saved-overlay.ts:28-39)增加按当前模式过滤参数
   (纯函数,可测),map-shell 传当前 canonical mode。domain 模式收藏功能保持现状。
2. **列表层 kind 守卫**:work 模式的 catalog 在客户端入口(`loadWorkViewport` 返回后,或
   map-shell 落库处)确保只含 `kind:'recruitment'`;对 `runPOIPipeline` 的输入或
   `loadWorkViewport` 的结果加 `isRecruitmentPoi` 过滤(服务端已过滤,客户端兜底防缓存污染)。
3. **mode-cache kind 校验**:`readModeCache`(mode-cache.ts)在 `isPoi` 之外增加按模式的
   kind 校验——recruitment 模式缓存只接受 kind:'recruitment',domain 只接受 kind:'domain'
   (不匹配的整条缓存作废)。若需要 bump `MODE_CACHE_VERSION`(现 6)使旧污染缓存失效,请做
   并在汇报说明。
4. **验证**:
   - work 模式地图显示**工作模式收藏的公司**(带岗位);**不显示地点收藏**(kind:'domain')。
   - domain 模式地图显示**地点收藏**;work 收藏不在主地图显示。
   - work catalog 无 kind:'domain' 行(控制台/代码检查 + 加日志验证)。
   - 模式切换后 work 缓存不被 domain 行污染(还原后仍只有 recruitment)。
   - 现有收藏功能(各模式各自的)回归正常。
