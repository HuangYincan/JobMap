## 根因(主 Agent 探索定位)

- `map-shell.tsx:799-802` 数据耗尽判定 `const noMore = canonicalMode(mode) === "domain" && beforeLen > 0 && data.length <= beforeLen` —— **仅对 domain 生效**。
- `noMoreRef`/`setNoMoreData`(map-shell.tsx:176-177)只在该行被设置 → **work 模式从不为 true**。
- `atCap`/`noMore` props 传给两个列表 UI 时同样 domain-gated(map-shell.tsx:1965-1966 桌面、
  2488-2489 移动)。
- `handleNeedMore`(map-shell.tsx:1129-1139)对 work 只有 `loadingRef` 守卫,无 cap/noMore 短路 → 每次滚动无限递增 `pageOffset`。
- `loadWorkViewport`(viewport-search.ts:373-391)短页 break(:388)不上报"无更多"给调用方。
- `poi-list.tsx:165-178` 渲染:`atCap` →「已达加载上限」,`noMore` →「没有更多结果」,`loadingMore` → spinner(硬编码字符串,非 i18n)。

## 任务

1. **让 work 模式也有数据耗尽判定**:把 `noMore` 判定的 domain 门放开(work + domain 都算),
   或为 work 增加等价判定——工作模式加载到页面返回短页/0 新增时,视为"已加载全部"。
   - 注意:work 是**增量合并**(`loadWorkViewport` 用 `existing` 合并),判定口径应与 domain 的
     `beforeLen > 0 && data.length <= beforeLen` 对齐;若 viewport-search 有更准确
     的"到底"信号(如短页 break),可让 `loadWorkViewport` 返回 `{ pois, noMore }` 或通过
     onBatch 上报。
   - **不要**用 domain 的 `DOMAIN_POI_HARD_CAP`(1000)——work 有自己的 `POI_HARD_CAP`(3000,
     viewport-search.ts:56),cap 语义不同。work 的"已加载全部"指数据源到底,不是 cap。
2. **atCap/noMore props**:放开 domain 门,让 work 的 noMore 能传给两个列表 UI
   (map-shell.tsx:1965-1966 + 2488-2489),使 sentinel 停止并显示「没有更多结果」。
   - work 是否也该有 atCap(已达 3000 上限)?建议:atCap 留给 domain(1000 cap);
   work 只有 noMore(数据到底)。文案复用「没有更多结果」。
3. **`handleNeedMore`**:work 分支加 noMore 短路(参照 domain 的 1132-1135),防止到底后仍递增。
4. **验证**:
   - 工作模式滑到底 → 显示「── 没有更多结果 ──」,spinner 停止,不再发请求。
   - 数据未到底时无限滚动仍正常(增量加载)。
   - domain 模式行为不变(仍「没有更多结果」/「已达加载上限」按原逻辑)。
   - 视口切换(moveend/zoomend)重置 noMore 的时机与 domain 一致(视口替换时复位)。
