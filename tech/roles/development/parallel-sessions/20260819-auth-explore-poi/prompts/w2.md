# WS w2 — 账户密码登录与注册(auth-password)

> 批次:20260819-auth-explore-poi | worktree: `/Users/acccan/dm-wt-w2`(已预建,分支 `feature/auth-password`)

## 背景

当前登录只有**演示用** OTP(手机/邮箱,固定验证码 000000,`/api/auth/otp/send|verify`)与**演示用** 社交登录(`/api/auth/oauth` 静态映射 github/google/wechat:demo)。会话机制:httpOnly cookie `dm_session`(24 字节随机 + HMAC-SHA256,14 天 TTL,`lib/http-session.ts` + `lib/session-store.ts`),服务端按需读取 `readSessionUser()`;存储双路径:有 `DATABASE_URL` 走 Postgres(`lib/account-store.ts`),否则内存 Map(`lib/db.ts`)。`AccountUser = { id, displayName, accountLabel, avatarUrl?, phone?, email?, provider, preferences }`(`lib/account.ts:40-50`)。用户表唯一键 `subject`(provider:subject),迁移在 `db/migrations/005_accounts_sessions_history.sql` 与 `007_profile_prefs_oauth.sql`(provider CHECK: phone,email,github,google,x,wechat)。**全仓库无 username 列、无 password 列、无密码登录路由。** 测试无需 DB(no-DB test gate)。

## 任务(用户需求:做好账户密码登录功能与注册功能)

1. **DB 迁移**(新文件 `db/migrations/00X_credentials_auth.sql`,编号接现有最大):
   - `users` 加 `username` 列(唯一索引,lower(username));加 `password_hash` 列(可空,仅 password provider 用户有)。
   - 或等价方案:建 `auth_credentials` 表(user_id 外键 + username unique + password_hash)——二选一,选与现有 `auth_identities`/`users` 结构一致、改动最小的方案(读现有迁移后自裁,写清理由)。
   - provider CHECK 扩展支持 `'password'`(若 CHECK 是硬约束,注意迁移幂等/兼容既有行)。
   - **注意**:迁移 apply 是 Env-only,本 worker **不 apply**(boss 会记 deferred)。但代码路径必须考虑「迁移未 apply 也能跑测试」(no-DB 内存 store 不受影响)。

2. **密码哈希**:用 `node:crypto` 的 `scrypt`(带随机 salt,参数化存储格式如 `scrypt$N$r$p$salt$hash` 或 node 风格),**不新增依赖**(npm install 被禁止)。哈希/校验函数放 `lib/account-store.ts` 或新 `lib/password.ts`,导出 `hashPassword(password)` / `verifyPassword(password, stored)`。

3. **Store 层**(`lib/account-store.ts`):
   - `registerWithPassword(username, password, displayName?)` → 创建 user(subject=`password:<username>`)+ 存 `password_hash` + `username`;username 冲突返回明确错误(409)。
   - `loginWithPassword(username, password)` → 校验 → 返回 user;失败统一返回 401「账号或密码错误」(不泄露哪个错)。
   - 内存 store 与 Postgres store 两条路径都实现;session 复用现有 `createSession`/`readSession` 机制(`session-store.ts`),登录/注册成功后照现有 OTP 流程写 cookie(`http-session.ts` 已有 `setSessionCookie`)。

4. **API 路由**(新目录 `src/app/api/auth/password/`):
   - `POST /api/auth/password/register` `{ username, password, confirmPassword? }` → 校验(用户名 2-32 位,字母/数字/下划线/中文;密码 ≥ 8 位)→ 注册 + 自动登录(写 cookie)→ `{ ok: true, user }`。重复用户名 409,参数错 400。
   - `POST /api/auth/password/login` `{ username, password }` → 登录成功写 cookie → `{ ok: true, user }`;失败 401。
   - 返回的 `user` 形状与 `/api/auth/me` 一致(AccountUser);`accountLabel` 用户名登录时为 username。

5. **`lib/account.ts`**:`AccountUser` 加 `username?: string`;`AuthProvider` 类型加 `"password"`(若需要)。

6. **UI(`src/components/auth-modal.tsx` + `.module.css` + `lib/i18n.ts`)**:在现有方法 tab(手机/邮箱/其他)中新增**「密码」tab**(即方法行变 手机 | 邮箱 | 密码 | 其他;选中蓝下划线,悬停浅蓝,均沿用现有 `.method`/`.methodActive` 样式语义)。密码 tab 内:
   - **登录模式**(默认):账号(用户名)输入框 + 密码输入框(类型 password,`autoComplete="username"`/`"current-password"`)+ 绿色主按钮「登录」(禁用态同现有逻辑:空则禁用)+ 底部「没有账号?立即注册」蓝色文字链接 → 切注册模式。
   - **注册模式**:账号 + 密码(≥8 位)+ 确认密码 + 绿色主按钮「注册」+ 底部「已有账号?去登录」蓝色链接。前端先做一致性校验(两次密码一致、长度),错误与接口错误统一显示在现有 `.error` 区域。
   - 成功(登录或注册)后照现有 `onSignedIn()` + `onClose()` 收尾(注册即自动登录)。
   - 布局 ASCII(遵循现有 auth-modal 结构:promo 玻璃区 + 表单区 + 关闭 X):
     ```
     ┌──────────────────────────────────────────┐
     │ [DM promo glass]                          │
     │  手机 | 邮箱 | 密码 | 其他       (tab 行)  │
     │ ───────────────────────────────────────── │
     │  账号                                     │
     │  ┌──────────────────────────────────────┐ │
     │  │ 用户名                                │ │
     │  └──────────────────────────────────────┘ │
     │  密码                                     │
     │  ┌──────────────────────────────────────┐ │
     │  │ ●●●●●●●●●                           │ │
     │  └──────────────────────────────────────┘ │
     │  [ 登录(green) ]                          │
     │  没有账号? 立即注册(blue link)            │
     │  (注册模式: + 确认密码 + [注册(green)]    │
     │   + 已有账号?去登录(blue link))           │
     └──────────────────────────────────────────┘
     ```
   - 移动端 ≤720px 行为沿用现有规则(隐藏 promo、tabs 左对齐、44px 触控)。
   - i18n 新增键(zh/en 都加):账号/用户名(username)、密码(password)、确认密码(confirmPassword)、登录(signIn 已有)、注册(register)、没有账号?立即注册(noAccountRegister)、已有账号?去登录(hasAccountLogin)、密码至少 8 位(passwordTooShort)、两次密码不一致(passwordMismatch)、账号已存在(usernameTaken)、账号或密码错误(invalidCredentials)等。

7. **测试**(`server/tests/`):密码哈希/校验单测;注册/登录逻辑(内存 store 路径)成功与失败分支;API 层可加 route handler 单测(照现有 auth 测试模式,先看 tests 里 otp/oauth 怎么测的)。保持 `npm test` 全绿(现有 296+ 通过)。
