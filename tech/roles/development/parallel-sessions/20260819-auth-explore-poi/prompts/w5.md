# WS w5 — 「最近」点击回到实体(recent-entity)

## 背景与根因(已探明,勿再大范围排查)

- 存储:游客 → localStorage `dm.guest-search-history.v1`(cap 30,`src/lib/guest-search-history.ts:12-13,56`);登录用户 → `/api/me/search-history`(`search_history` 表,`lib/account-store.ts:284-354`)。客户端统一状态 `searchHistory`(map-shell.tsx:252,`refreshHistory` :324-336)。
- 条目形状:`SearchHistoryEntry = { id, query, mode, createdAt }`(`src/lib/account.ts:56-61`)——**只有查询串**,无实体信息。
- 当前点击:`onPick` → `handlePickRecent`(map-shell.tsx:1756-1760)→ `replayRecentSearch`(`lib/modes.ts:302-312`,只规范化 mode)→ `openExploreSearch`(map-shell.tsx:1739-1754)→ 仅 `setQuery` + 打开探索栏/抽屉。**不移动地图、不开详情卡**——用户还得重新搜一遍。
- 「回到实体」可参照的成熟模式:`handlePickSaved`(map-shell.tsx:1261-1280):`resolveSavedForFly` → `setSelectedId`/`setDetailPoi` → `flyToLocation`(map-shell.tsx:122-134,`map.setZoomAndCenter(zoom,[lng,lat],false,600)`)。`SavedPlace` 类型已带 `poiId,name,kind,address,lng,lat`(account.ts:63-73);`SearchHistoryEntry` 目前全没有。
- 详情拉取:`fetchPOIDetail(poiId, mode)`(`lib/api.ts:103-105`,用于 map-shell.tsx:1579);`/api/pois/[id]` 走 `loadServerCatalog`(**全国数据**,跨城市可用)。
- 记录时机:条目产生于「提交搜索/选定建议」路径(worker 自行定位:搜索提交、`applyTagSuggestion`、suggestion 选中 `handleSelectSuggestion` map-shell.tsx:1520-1523 等写 history 的地方)。
- 跨城市场景(用户例:在杭州,历史记录有北京的「字节跳动」):只要记录时把实体 `id/name/lng/lat` 存下,点击时 `flyToLocation` + `fetchPOIDetail(id)` 即可**不依赖当前视口**。

## 任务(用户需求:历史记录点击应回到那个实体,而非作为搜索框输入)

1. **数据模型**:`SearchHistoryEntry` 增加可选实体引用字段(设计自裁,建议 `entity?: { kind: "company" | "poi"; id: string; name: string; lng?: number; lat?: number; address?: string }` 或平铺字段——选与 `SavedPlace` 风格一致的方案)。旧条目无 entity → 保持纯搜索回放。
2. **记录**:在写 history 的路径上,**当查询确定落在一个实体时**(例如 suggestion 选中/`applyTagSuggestion` 带 poiId、或搜索结果唯一命中公司)把实体引用一并记录;纯关键词查询不记。记录点要同时覆盖:
   - 游客 `guest-search-history.ts`(条目写入处,含 cap 逻辑);
   - 登录用户 `/api/me/search-history` POST(route + `account-store.ts`)。
   - 兼容性:旧 localStorage 数据(无 entity 字段)与旧 DB 行都要能被读取器容忍(可选字段容错)。
3. **点击**:`handlePickRecent`(map-shell.tsx:1756-1760):
   - 有 entity → 走 `handlePickSaved` 同款逻辑:fly 到 `lng/lat` + 打开该实体详情(`fetchPOIDetail(entity.id, mode)`;work 模式 `poiId` 对应 company;domain 模式对应 poi)+ 选中态;移动端同步开抽屉详情。
   - 无 entity → 维持现状(搜索回放)。
   - 找不到/拉取失败 → 优雅降级回搜索回放,不白屏。
4. **DB 迁移**(新文件 `db/migrations/00X_recent_entity.sql`,编号接现有最大):`search_history` 加可空 entity 列(jsonb 或平铺,自裁,与第 1 步模型一致)。
   - **迁移 apply 是 Env-only,不执行**(boss 记 deferred)。
   - **硬约束**:迁移未 apply 时系统不能崩——`/api/me/search-history` 的 SELECT 必须容忍 entity 列不存在(例如运行时探测列存在性,或按返回字段有无自适应),测试无 DB 也能绿。
5. **展示**(`recent-panel.tsx`,可选小改):有 entity 的行可在 meta 处显示城市/类型小标签(如有存),不强制;保持现有行样式语义。
6. **测试**:guest-search-history 实体持久化与旧数据兼容(扩展现有 `guest-search-history.test.mjs`);record 路径的实体字段断言;`component-contracts.test.mjs` 若有 recent 相关静态契约保持绿;点击回放逻辑的纯函数分支测试(如可测)。保持 `npm test` 全绿(现有 296+)。
