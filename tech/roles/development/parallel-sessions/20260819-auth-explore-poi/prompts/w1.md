### 2. 比例尺控件崩溃(控制台报错根因)
- `handleResize`(map-shell.tsx:630-642):`:634` `map.removeControl(scaleControl)`、`:639` `map.addControl(scaleControl)`;`:643` 注册 window resize 监听。
- **监听器泄漏**:`cleanup` 闭包(map-shell.tsx:588-596,内含 `:594` removeEventListener)由 `createMap` 返回(`:687`),但 `initMap`(map-shell.tsx:484-488)调用 `createMap(...)` **没有接收返回值**,cleanup 成了孤儿永不执行。effect 实际 cleanup(map-shell.tsx:690-710)只 `map.destroy()`(:692),**没移除 resize 监听**。
- 后果:地图销毁后(组件卸载 / Next dev Fast Refresh 重挂载 / 路由重挂)泄漏的 `handleResize` 仍引用已销毁的 map;下一次 resize → removeControl/addControl 摸到销毁的容器 → 正是用户报的 `Cannot read properties of undefined (reading 'removeChild')`(map-shell.tsx:634)/`appendChild`(:639)。
- 附带竞态:`AMap.Scale` 插件回调(map-shell.tsx:617-627)若在 resize 前执行完成,会被 `handleResize` 覆盖重建;反之若 resize 先触发,回调会**第二次 addControl**,产生两个比例尺。

### 3. POI 停止加载/不新增的根因(按严重度排序)
- **(A) 一次失败永久 noMore,无重试** —— 最强嫌疑。任何 domain 路径错误落到 `onBatch(existing); return existing`(poi-service.ts:88-92、124-128、180-183);work 路径失败返回 `[]`(viewport-search.ts:356)。主 load 算 `noMore = beforeLen > 0 && data.length <= beforeLen`(map-shell.tsx:830-831)→ `true` 并存储(:847-848)。`handleNeedMore` 在 `noMoreRef` 为 true 时硬返回(map-shell.tsx:1211)。一次瞬时网络/AMap 错误 → 滚动哨兵永久失效,显示「── 没有更多结果 ──」,直到平移地图或手动刷新。
- **(B) `loadingRef` 无限卡死,AMap 无超时**。`handleNeedMore`(:1215)与 viewport loader(:892-897)都门控 `loadingRef`(只在 `finally` 释放,:856)。`searchPOI` 只等 AMap `complete`/`error` 事件(amap-api.ts:343-368),**无超时**——PlaceSearch 永远不回调(配额/脚本异常)时 `load()` 永久 await,后续一切加载被堵死。
- **(C) `skipFetch` 提前 return 吞掉待重放的视口刷新**。skipFetch 分支在 try/finally 之前 return(map-shell.tsx:748-752);若此前视口刷新设了 `viewportRefreshPendingRef`(map-shell.tsx:892-897),finally 里的重放逻辑(:860-863)被跳过;叠加模式切换缓存恢复会 arm skipFetch(map-shell.tsx:1403-1414),结果列表冻结到下一次地图移动。
- **(D) domain noMore 误判**。noMore 用**原始 catalog** 长度比较(map-shell.tsx:830-831),但可见列表是**过滤后**的 `pois` memo;且 domain-local 查询带 common 过滤(`rating>0 OR photos OR tier<=3`,hz-poi-store.ts:91)与 offset 上限 1000(hz-poi-store.ts:142-143)——DB 对当前视口返回 0 新行时 noMore=true,即使视口内还有合法 POI。**注意 `/api/pois/domain-local` 响应已带 `total`(route.ts:68-74),work 的 `/api/pois` 响应也带 `total`(route.ts:52-57,client 现在不读)**——用服务端 total 判断 noMore 比本地长度比较可靠。
- **(E) 旧批次被 epoch 丢弃**是**有意设计**(防 POI 混串,viewport-search.ts:263-281),不要改。

## 任务

1. **比例尺控件生命周期修复**(map-shell.tsx):
   - 让 `initMap` 持有/执行 `createMap` 的 cleanup(正确接线 `:484-488` 与 `:588-596`、`:687`);effect cleanup 里确保 `removeEventListener('resize', handleResize)`。
