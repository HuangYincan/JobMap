## 背景

用户反馈:「前端看不到」新入库公司(993 家)。根因(已确认):`server/src/lib/server-catalog.ts:53` 的 `.filter((poi) => poi.positions.length > 0 && hasPlausibleCoord(poi))` —— **无坐标站点进不了 POI**,地图与搜索都不可见。大量 drops 的 `site.city` 是多城市字符串(「北京、杭州、上海、成都、深圳等」),无法 geocode 成单点。项目已有 `CITY_CENTERS`(city-centers.ts:18,城市中心坐标表,domain 聚合在用)与 `cityCenter(city)`(L63)。

## 任务

**多城市字符串拆分 + 单城市无坐标补中心点**,让有岗位的公司全部上地图(城市级标记):

1. 读 `server/data/recruitment/{radar,qqdoc-jobs,qqdoc-official,official-career}/**/*.json` 的结构与 `server/src/lib/city-centers.ts`(`CITY_CENTERS` 键列表、`cityCenter` 归一逻辑)、`server/src/lib/recruitment-adapters/`(drops 契约:site.id 唯一性、positions.siteId 引用)。
2. 写拆分脚本(`server/scripts/split-city-sites.mjs`,自裁):
   - **多城市字符串** site(如「北京、杭州、上海」「北京/上海/苏州」「上海 北京 深圳 广州」)→ 解析出城市列表(分隔符:,、/ 空格;剔除「等」「全国其他」「海外」「线上」「远程」等非城市 token;城市名匹配 `CITY_CENTERS` 或常识别名如「魔都/羊城」不处理,只处理可归一城市)→ **每城市一个 site**:`city` = 城市全称(如「北京市」,与 CITY_CENTERS 键归一风格一致),坐标 = `cityCenter(city)`。
   - **单城市字符串但无坐标** 的 site(如「上海市」且 location 空)→ 补 `cityCenter` 坐标(该城市中心点)。
   - **已有坐标的 site 不动**(街道级 geocode 坐标优先保留)。
   - **岗位挂载**:site.positions(或公司级 positions)按 `position.city` 匹配拆分后的城市站点;无法匹配的岗位挂到「公司主站点」(原 site 保留为主站点,id 不变);**positions.siteId 必须同步更新**(引用一致性)。
   - 幂等:重复运行不重复拆分(已拆分的 site 有中心坐标 → 跳过)。
   - 拆分后原多城市 site:保留为「主站点」(city 取第一个城市或原字符串?自裁,但**保留原字符串会再次触发拆分**—— 需标记已处理或改成单城市)。
3. **测试**:拆分纯函数单测(字符串解析:分隔符/「等」/「全国其他」剔除;城市归一;去重;岗位挂载匹配)。风格对齐现有 vitest。
4. **不跑真实 geocode**;不调任何外部 API。

## 关键约束

- **串味防御兼容**:城市中心点必须落在 `CITY_REFERENCE_BOXES` 对应城市框内(上海中心 121.47/31.23 ∈ [120.8,122.1]×[30.65,32.0] ✓)—— 中心点取自 `cityCenter()`,天然满足;不要自己发明坐标。
- **徽章语义**:拆分后徽章 = 真实招聘覆盖城市数(城市级站点),是本次变更的预期结果。
- 已有精确坐标的站点(如 4b05e64 geocode 过的)不受影响。
- 只处理**有岗位的公司**(无岗位公司拆了也不显示,浪费;boss 已确认口径:只拆有 positions 的)。
