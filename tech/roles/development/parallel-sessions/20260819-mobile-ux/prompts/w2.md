## 背景(用户明确指定)

移动端(≤767px frost 抽屉)两项交互问题:
- **交互 1**:选中一个二级卡片 → 进详情 → back to list 后,视觉上应停留在**以该卡片为第一张
  卡片**的位置(滚动位置不重置)。
- **交互 2**:卡片已显示蓝色已选状态时,点二级卡片的其他位置(如 **margin 边缘处**)应**取消选中**。

## 任务

### 1. 返回后滚动位置保留(交互 1)
- 给 `.drawerContent` 加 ref:`const drawerContentRef = useRef<HTMLDivElement>(null)`。
- **打开详情前保存**:移动端卡片 onClick 链(`2516-2522`)里,`setDetailPoi(poi)` 之前
  `drawerScrollRef.current = drawerContentRef.current?.scrollTop ?? 0`。
- **返回后恢复**:两条返回路径(`2159-2162`、`2204-2209`)都只清 detailPoi。加一个
  `useLayoutEffect`(key 为 detailPoi,当其变为 null 且 ref 存在时)`drawerContentRef.current.scrollTop
  = drawerScrollRef.current`——layout effect 在重挂载 DOM 更新后、绘制前执行,保证容器已存在。
- 边界:
  - 模式切换(`handleModeChange`)或新列表加载时应清 `drawerScrollRef`(避免把旧视野的滚动带到新列表)。
  - 保存时机只在**移动端卡片打开详情**路径;桌面 openDetail(secondary-sidebar)不涉及。
  - 若保存值为 0(从未滚动),恢复 0 是安全的。
- 效果验证:列表滚动到某卡片 → 打开详情 → 返回 → 该卡片仍为第一张可见卡片(蓝色选中),滚动未重置。

### 2. 边缘点选取消选中(交互 2,仅移动端)
- `poi-list.tsx`:
  - `POIList` 新增可选 prop `onDeselect?: () => void`。
  - `.cardSlot` div(`150`)加 `onClick`:`onDeselect ? () => onDeselect?.() : undefined`。
- `poi-card.tsx`:`<article>` onClick(`166`)加 `e.stopPropagation()`,使点卡片自身不冒泡到
  cardSlot 触发取消选中(点卡片仍走原 select+openDetail 逻辑)。
- `map-shell.tsx`:移动端 POIList(`2512`)传 `onDeselect={() => setSelectedId(null)}`;桌面
  secondary-sidebar(`434`)**不传**(保持现状,桌面无此交互)。
  - 取消选中时同时清 `highlightedId`(如有,与 map-shell.tsx:647-652 的清除口径一致);
    **不关闭 detail**(在列表视图下 detail 本就为 null)。
- 交互图(目标,移动端):
```
┌──────────────────────────┐
│ …                        │
│ ┌──────────────────────┐ │
│ │ 卡片 A(蓝色已选)       │ │ ← 点卡片本体:select+进详情(不变)
│ └──────────────────────┘ │
│   ↑ 空隙/margin(12px)     │ ← 点这里:取消选中(蓝色消失)
│ ┌──────────────────────┐ │
│ │ 卡片 B               │ │
│ └──────────────────────┘ │
└──────────────────────────┘
```
- 注意:移动端点卡片会同时 select+开详情(2516-2522),所以「已选但未进详情」的蓝色态出现在
  从详情返回后——正是本交互的目标场景。点空隙取消后,selectedId/highlightedId 清空、地图 marker
  选中样式消失。
