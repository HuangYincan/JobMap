## 背景

geocode 链当前为 AMap → 百度 双兜底(`server/src/lib/site-geocode.ts`)。`TENCENT_MAP_KEY` 已在 `.env.local` 与 `.env.example` 预埋(此前一个并发批次只同步了 env,代码未接入)。用户要求接上腾讯第三级兜底,缓解 AMap place-text 100 次/天 + 百度 302 的配额瓶颈。

腾讯位置服务(Web 服务 API,公开文档 https://lbs.qq.com/service/webService/webServiceGuide/webServiceOverview):
- **地点搜索**(公司名检索,等价 place-text):`GET https://apis.map.qq.com/ws/place/v1/search?keyword=<公司名>&boundary=region(<城市>,0)&key=<KEY>`(boundary 城市形式 `region(上海,0)`;或 boundary=nearby(lat,lng,radius) 不可用,公司名检索用 region)
- **正地理编码**(地址→坐标):`GET https://apis.map.qq.com/ws/geocoder/v1/?address=<地址>&key=<KEY>` → `result.location.lat/lng`
- **逆地理编码**(坐标→地址/城市验证):`GET https://apis.map.qq.com/ws/geocoder/v1/?location=<lat>,<lng>&key=<KEY>` → `result.address_component.city`(直辖市区级用 `district`)
- **坐标系**:腾讯与高德同为 GCJ-02,直接兼容,无需转换(与百度 ret_coordtype=gcj02ll 同效果)
- 响应:`status === 0` 成功,非 0 为错误(如 3xx 配额/签名问题)

## 任务

在 `server/src/lib/site-geocode.ts` 加腾讯第三级兜底:

1. 读现有实现:`amapWebKey()` / `baiduWebKey()`(L185-187 附近,读 process.env)、`geocodeAddressRest`(L392-430,AMap→百度)、`placeTextSearchRest`(L617-670)、`regeoCityRest`(L715-760)—— 模式:每函数「主源 → amapUnavailable 判定 → 百度兜底」。
2. 新增:
   - `tencentWebKey()`:读 `process.env.TENCENT_MAP_KEY`。
   - `tencentGeocodeAddressRest(address, city)`:腾讯正地理编码;失败/非 0 返回 ok:false + reason(`tencent-status:N`)。
   - `tencentPlaceTextSearchRest(query, city)`:腾讯地点搜索(region boundary);解析 `data[0].location.lat/lng` + title/address。
   - `tencentRegeoCityRest(lng, lat)`:腾讯逆地理;解析 `address_component.city/district`(与 regeoMatchesTarget 的直辖市逻辑对齐:北京/上海 regeo city 可能为空 → district/province 兜底)。
   - **兜底链扩展**:三个主函数在 AMap 失败(quota/网络)且百度也失败时,再试腾讯;`amapUnavailable` 语义保持(为 true 时 sleep 加长已有);错误传播保留(成功 provider 记为 'tencent')。
   - **限流纪律**:腾讯失败也走 sleep 340ms;不重试轰炸;连续失败交给现有 QUOTA_SHORT_CIRCUIT(quota 类 reason 判定需要覆盖 tencent-status:XX —— 自裁:哪些 status 算配额类(3xx/配额码)需并入 shouldShortCircuitQuota 的判定或映射为已知 reason,保持短路可用)。
3. **测试**:`server/tests/site-geocode.test.mjs` 扩展:
   - 腾讯响应解析纯函数(mock fetch:成功/status 非 0/网络错误)
   - 兜底链顺序(AMap 失败 → 百度失败 → 腾讯成功;provider='tencent')
   - 短路兼容(腾讯配额类失败计入 quota 类,连续 5 触发短路)
   - 直辖市 regeo 兜底(district/province)
   - 对齐现有 vitest 风格。
4. **key 验证**(允许少量真实请求):dry-run 1-2 次腾讯 API(如正向 geocode「杭州市西湖区文一西路969号」+ 地点搜索「得物」region 上海),确认 key 有效、响应格式与假设一致;失败如实记录(可能 key 无权限/配额 0)。**不跑 geocode:sites:apply 全量**(网络留给用户)。
