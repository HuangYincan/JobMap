## 任务(确定性规则,不允许自由发挥)

### 1. 读入结果
- 遍历 `results/batch-*.json`(主仓库),解析 JSON 数组(末行 ADDR_BATCH_DONE 排除)。
- 每条:site_id / address / source_url / address_type / confidence / note。
- 多城市拆分条目(site_id 带 `-城市` 后缀,如 `qqj-兆芯-site-上海`)归属原 site_id(取 `-` 前段?注意 site_id 本身可能含 `-`,如 `qqj-中国远洋海运集团-site-hq`——**用「按原清单 site_id 精确匹配」**:主仓库 `city-only-list.json` 是权威清单,含原始 site_id;results 的 site_id 若不在清单中,去掉最后一段 `-<城市>` 再匹配,仍不中则记入报告)。

### 2. 聚合规则(每 site 一条地址)
- 一个 site_id 多条结果时,选 **confidence: high > medium > low;同 confidence 时 address_type: office > registered**。
- 无 address 的条目不参与(保持该站点无地址,记入报告:count-null)。

### 3. 回填(写本 worktree 内 drop JSON)
- 找到 `city-only-list.json` 中该 site_id 对应的 `file`(如 `qqdoc-jobs/qqj-兆芯.json`),读对应 JSON(单对象或数组),定位 `sites[]` 中 id 匹配的 site:
  - `site.location = { ...(site.location ?? {}), address: <找到的地址> }`(location 是空对象 {} 时直接赋 `{ address }`)。
  - `site.city = <从地址提取的城市>`(见 4);提取失败 → 保留原值,记入报告:city-unresolved。
  - 不碰其他字段(province / name / id / careerUrl 等)。
- 写回保持 `JSON.stringify(obj, null, 2) + "\n"`(与现文件格式一致;先 `git diff` 确认只有目标字段变化)。

### 4. city 提取(确定性)
- 地址含「省/市/自治区/特别行政区」:取首段城市名——直辖市(北京/上海/天津/重庆)取「北京市」格式;省+市取「XX市」;地址以英文开头或为海外格式:取最后一个逗号后的段(如 "Waltham, MA" → 取 "Waltham, MA" 或 "Waltham")。
- 已知城市别名表可参考 `server/src/lib/recruitment-import.ts` 的 TARGET_CITIES 与 city 归一逻辑(只读参考,不改)。
- 提取结果形如「北京市」「深圳市」「San Carlos, CA」等;空/无法识别 → city-unresolved。
