## 背景

用户目标:「对于只有城市没地址的 poi,优先上网寻找其地址,一般网上都有的」。

「只有城市没地址的 POI」= drop JSON(radar / official-career)中 site 有 `city`/`province` 但
`location` 缺失(无 address、无坐标)——即 `siteNeedsGeocode` 为 true 且 `location.address` 缺失的站点。
现有链路 `server/scripts/geocode-sites-apply.mjs` 对这些站点只做**一次「公司名」place-text 检索**
(主循环 L288 `const query = cleanCompanySearchName(company.name)` → L334 `searchCompanyPoi(query, target)`),
命中 POI 带 address 则回填(L390-395 已回填,含区名前缀)。unresolved 积压主因:
`no-pois` / `gradeOfficePoi` 低置信 / `regeo-outside`。已知精度缺口:**检索 query 不含站点名**
(同公司同城多 office 靠 `(query,province,city)` memo 共享同一命中;站点名如「网易 杭州研究院」
本可精确定位,却只用裸公司名搜)。

配额背景:AMap place-text 100 次/天(有配额短路)、地址正向 geocode 5000 次/天、
百度/腾讯兜底链、`(query,province,city)` memo 只缓存成功命中。地址-城市一致性闸门
(`addressConflictsWithCity`)、regeo 城市/区级双闸门、override 行为、配额短路均不得改变。

## 任务

对「只有城市、无地址」的站点,把网络检索当首要通道,提高拿到「地址+坐标」的命中率。
实现自裁,但需满足:

1. **检索 query 策略增强**(核心):
   - 无地址站点:站点名存在时,生成「公司名 站点名」精确候选(如「网易 杭州研究院」)
     与裸公司名候选;推荐先精确后宽或先宽后精确均可(自裁,依据对命中率/配额消耗的权衡),
     但**每站点 place-text 调用 ≤ 2 次**;memo 覆盖所有变体 key,不重复消耗。
   - 地址-城市一致性闸门、regeo 校验、override 优先级等既有行为保持不变。
2. **地址缺失补查**:命中 POI 的 `address` 缺失/过短(如空串或仅区名)时,尝试补查
   (如 AMap place/detail,或换变体再检索);补查同样受配额约束,不得绕过配额短路。
3. **回填保障**:确认所有写回路径 `location.address` 都有值(L390 区名前缀逻辑保留);
   无地址站点的 resolution 里 address 非空。
4. **测试**(对齐 `server/tests/` 现有 vitest 风格,可对 `placeTextSearchRest` 注入 stub 计数):
   - 无地址站点生成的 query 变体顺序与 memo key(同 query+region 第二次不发出请求 / 不同变体不同 key)
   - 精确候选未命中回落到宽候选
   - 命中 POI address 缺失时触发补查、补查失败不写回
   - 地址回填到 `location.address`、低置信不回填
   - 既有 geocode 相关测试不得回归(geocode-providers / quota-short-circuit / place-memo / plan-count)
5. **文档**:在 `tech/roles/data/` 下更新/新增来源记录,说明「无地址站点网络查地址」通道
   (检索源仍是 AMap/百度/腾讯 place-search,已登记;新增的是 query 策略与补查行为)。
   `make docs-check` 必须通过。

**不跑真实网络**(geocode REST 留给用户,Env-only)。**不 merge/push/切分支。**
