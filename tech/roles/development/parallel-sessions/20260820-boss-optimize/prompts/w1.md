# Workstream w1 — 修复 B3 城市聚合假数据/漏聚合(坐标↔城市标签防御)

## 背景(已查明的根因,2026-08-20 boss 派发)

B3 城市聚合(zoom≤8 徽章)是**纯前端**实现:`server/src/lib/city-cluster.ts` 的 `clusterCities(pois, zoom)` 按 `poiCity()` 即 **`poi.sites[0].city` 标签**分组(city-cluster.ts:37-41),`group.count += 1`(line 73)计「公司-站点数」。

三个验收症状根因:

1. **「成都假聚合」**:DB 有 147 条「city=深圳/成都/北京/上海但坐标=杭州」串味行(76 公司,914 岗位,2026-08-19 数据修正已记 deferred)。查询层唯一防御 `cityBoundsConsistencySql`(`server/src/lib/spatial-query.ts:141-151`)被 `singleCityReference`(:122-134)门控——**bbox 面积 > `CITY_VIEW_MAX_AREA_SQ_DEG`=6(:110)时返回空片段**,zoom≤8 全国视野必然超过 → 防御失效 → 串味行按 city 标签被分进「成都」徽章。下钻 zoom 11 到成都后这些 pin 实际在杭州坐标,所以「成都明明没岗位却有聚合」。
2. **「数量不正确/不稳定」**:徽章 N = 输入 marker 池按标签分组的 POI 数;池受 `maxTierForZoom(zoom)`(`server/src/lib/lod.ts:26-29`,=zoom)过滤且**只增不减**(`server/src/lib/use-work-viewport.ts:203-205`)——从城市视野缩出时池里残留 tier>zoom 的公司,同一 zoom 不同导航历史计数不同。验收标准:徽章 N 应等于「该 zoom 下该城市下钻后个体 pin 的数量」。
3. **「贝达药业未被聚合」**:数据存在(seed `seed-data.ts:1070-1099` betta-hangzhou 杭州临平 120.258/30.438;official-career drop `server/data/recruitment/official-career/betta-hangzhou.json` tier 6,3 open 岗位,导入归 city='杭州')。疑 DB 行过期(tier=12)或验收 zoom 层级,代码侧若无 bug 则记为「需数据层验证」(boss 合并后处理),但**必须**补一个离线/seed 路径下的测试证明 betta 在 zoom≥6 会进「杭州」徽章。
