## 需求(用户原话)

「将现在的地图POI加载逻辑改为按类加载,其默认情况下不加载POI,只有当用户选择好类,比如说购物、美食时,全量加载当前视图下这个类别的所有POI」

## 现状(已探明,勿再大范围排查)

- **分类下拉已存在**:domain 模式 FilterPanel 单选框(`MODES.domain.filters`,`src/lib/modes.ts:151-176`,category select,选项 = 9 个 big_type:餐饮服务/购物服务/风景名胜/体育休闲服务/交通设施服务/住宿服务/医疗保健服务/科教文化服务/公司企业),状态在 `filters: FilterState`(map-shell.tsx:216)。**当前是纯客户端过滤**:`pois = runPOIPipeline(catalog, {query, filters, sort, center})`(map-shell.tsx:1176-1185)→ 只过滤已加载目录,**选类零网络请求**。
- **服务端 categories 参数已通但客户端不发**:`fetchLocalPois`(poi-service.ts:144-202)只发 bounds/zoom/limit/offset/q(:150-160);服务端 route.ts:41-43 解析 categories(逗号分隔)→ `hz-poi-store.ts:83-88` `p.big_type = ANY($n)`。杭州外 AMap fallback 的 categories 参数也已存在(poi-service.ts:112-127 → amap-api.ts:717-730)。
- **自动加载两处**:① init `load()` effect(map-shell.tsx:749-896,mapReady && geoSettled 触发)② moveend/zoomend 视口 loader(debounce 800ms,map-shell.tsx:899-1039,domain 分支 :984-1024,`existing: []` 整体替换语义)。外加 suggestion 选中会 upsert 单个 POI(:1583-1591,保持)。
- **容量**:`DOMAIN_POI_HARD_CAP = 1000`(viewport-search.ts:65)、`DOMAIN_BATCH_SIZE = 50`(:71);domain-local API limit 上限 300 / offset 上限 1000(hz-poi-store.ts:142-143)。hz_pois 实测:餐饮服务 85,595 行、购物服务 154,139 行(视图内可能数千)。

## 任务

1. **默认不加载**:domain 模式无分类选择时,两个自动加载入口(init load 的 domain 分支 + 视口 loader domain 分支)直接跳过 fetch,目录保持空(地图无 domain marker,列表空态)。
   - 空态文案微调:i18n 新增「选择类别开始浏览」(zh)/「Pick a category to explore」(en),空态显示该提示(替换/附加现有文案,保持现有空态结构语义)。
2. **选类全量加载**:用户在下拉选「餐饮服务」等类别时:
   - 触发按类别加载:`fetchLocalPois` 增加 `categories` 参数(poi-service.ts:150-160 构造 query,`categories: [filters.category]`),杭州外 AMap fallback 同步传 categories(已支持)。
   - **全量**:循环 offset 拉完当前视图该类别的所有 POI(受 `DOMAIN_POI_HARD_CAP` 上限保护)。API limit 上限 300、offset 上限 1000——若循环到 offset 1000 仍未穷尽,以硬上限为准停止(「全量」= 尽力全量,受容量保护;汇报里说明该上限的取舍)。
   - 换分类:清空目录 + 按新分类重拉当前视图;清空动作不要落空缓存(writeModeCache 已跳过空目录,确认即可)。
3. **视口联动**:移动/缩放 → 按当前选中分类重拉新视图(现有 replace 语义,加上 categories)。未选分类 → 视口移动不拉取(第 1 点)。
4. **搜索豁免**:查询/建议路径保持现状(搜「肯德基」仍按名加载并 merge;suggestion upsert 保持)——搜索不受分类门控。
5. **分类过滤语义变化**:filters.category 从「过滤已加载目录」变为「驱动加载」;pois memo 的客户端 category 过滤保留(无副作用,类别数据一致性兜底)。minRating/price 仍纯客户端。
6. **空批次保护(顺带防同类 bug)**:视口 loader 的 domain 分支(onBatch 处 map-shell.tsx:1008-1009)与 work 分支(:960-961)加防御:**已有非空目录时,新批次为空 → 保留旧目录**(不整体替换为空;防 setBounds/flyTo 等程序化相机移动把目录冲空)。这是对 w5(收藏图层 bug)的纵深防御,两个 WS 各改各的。
7. **测试**:poi-service 的 categories 参数构造与分页循环;分类门控(无分类不 fetch);空批次保护;component-contracts 静态断言(门控逻辑/新 i18n 键);mode-cache 空目录不落缓存已有测试,确认兼容。保持 `npm test` 全绿(现有 328+)。
