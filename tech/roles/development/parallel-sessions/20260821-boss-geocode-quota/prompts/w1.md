## 背景

2026-08-21 实测 geocode:sites:apply 在**双配额耗尽**后不停止:

- AMap 地点检索(place-text):免费配额 100 次/天,已 100% 耗尽(infocode 10044)
- 百度地点检索兜底:返回 `{"status":302,"message":"天配额超限,限制访问"}`(实测 curl 复现)
- 脚本行为:每个缺坐标站点逐个尝试 → AMap quota → 百度 302 → 记 `unresolved` → **继续下一个**。~1800 个待 geocode 站点,耗尽后纯空跑数十分钟零产出,用户必须手动 Ctrl-C。

根因:geocode-sites-apply.mjs 主循环无「双配额耗尽 → 提前终止」短路;site-geocode.ts 的 `amapUnavailable` 标志只影响 sleep 时长,不终止。

## 任务

给 geocode 执行链加**配额短路**,耗尽即停:

1. 读 `server/scripts/geocode-sites-apply.mjs` 主循环(L149-330 附近)与 `server/src/lib/site-geocode.ts`(`amapUnavailable` / `baidu-status:302` 传播路径)。
2. 设计(自裁,最小改动,防误停):
   - **判定口径**:连续 N 个站点(建议 N=5)全部 unresolved 且 reason 均为**配额类**(`quota` / `baidu-status:302` / `no-key`)→ 判定双配额耗尽。
   - **防误停**:间歇性 `http` / `empty` / `parse` / `regeo-outside:*` 不算配额类;`baidu-status:401` 是并发限流(可重试)不算;只有 302 与 amap quota 算。
   - 触发后:**打印汇总(与正常收尾同款 REPORT 段)+ 一行醒目说明**(如 `QUOTA_EXHAUSTED: AMap+百度 双配额耗尽,已提前停止,剩余 N 站待下次运行`)+ 非零退出码(如 exit 2),并保留已写入的站点(drops 已有坐标的站点跳过逻辑保持不变,重跑幂等)。
3. **测试**:`server/tests/` 新增单元测试覆盖短路判定(连续 5 配额类失败 → 停;中间夹非配额类失败 → 不误停;配额类失败后恢复 → 不误停)。测试对齐现有 vitest 文件风格(可 mock `site-geocode.ts` 的调用,或抽一个纯函数 `shouldShortCircuitQuota(history, n)` 供测)。
4. 不跑真实 geocode(网络留给用户跑,配额明日重置)。
