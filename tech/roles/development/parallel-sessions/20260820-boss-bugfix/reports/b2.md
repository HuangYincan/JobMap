## 遇到的问题

1. **8.1/8.4 分桶语义**:初版测试按「8.1 仍为聚合桶」写(floor 边界),与实现冲突——`clusterCities` 是严格边界(`zoom > 8 → null`),且任务要求「聚合阈值不动」。按**严格边界**定稿:`clusterZoomForZoom(8.1) = 9`(个体桶),8.0→8.1 是聚合↔个体的唯一一次切换,8.1→8.9 内零重建;聚合区间内按 `floor(zoom)` 分桶(7→8 徽章计数合法变化)。测试 (c) 按此断言。
2. **markerPois 引用稳定性(实现中发现)**:若 work 分支直接 `mergeMapPois(pipeline(catalog),…)`,`pois`(listCatalog 依赖)进入 deps 后,每次视口批次仍会触发 markerPois 重算 → setPOIs 全池 setPosition。拆成 `workMarkerPois` + `markerPois` 两段,work 分支返回同引用,listCatalog 变化零 marker 触碰。
3. **刷新/筛选变窄的存量 pin**:add-only 下旧 pin 无法靠差分移除——由 visiblePOIIds 兜底(不在池内的 id 自动隐藏,实例保留);`setPOIs([])` 保留「空列表 = 清空」语义(与既有测试一致),刷新无 overlay 时真正释放实例。domain 换视野同理:旧 pin 隐藏不销毁(实例随会话累积,内存可控,换取零闪屏)。
4. **overlay pin 不随 LOD**:收藏 overlay 恒显示(与改动前行为一致),LOD 过滤只作用于池内非 overlay 的 recruitment pin;domain pin 无 tier 恒显示。
