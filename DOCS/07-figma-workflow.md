# Figma 设计工作流

## 🎨 核心规则

> ⚠️ **硬性要求**:任何前端代码编写之前,必须先创建 Figma 原型并获得用户批准。无例外。

这条规则适用于:
- ✅ 新页面开发
- ✅ 新组件开发
- ✅ UI 调整/优化
- ✅ 布局变更
- ✅ 交互流程变更
- ✅ 样式/主题修改

唯一例外:纯后端/数据库/爬虫工作(不涉及前端界面)

---

## 📋 工作流程

### 1. 创建 Figma 原型(AI Agent)

当接到前端开发任务时:

```markdown
**任务**: 实现招聘地图主界面

**步骤**:
1. ❌ 不要直接写代码!
2. ✅ 打开 Figma,创建原型设计
3. ✅ 参考设计规范(见下方"设计参考"章节)
4. ✅ 完成后,将 Figma 链接记录到实施文档
5. ✅ 通知用户:"Figma 原型已创建,请审查: [链接]"
6. ⏸️ 暂停,等待用户反馈
```

**Figma 原型应包含**:
- 完整的视觉设计(颜色/字体/间距/圆角)
- 交互状态(hover / active / disabled / loading)
- 响应式布局(桌面 / 平板 / 移动)
- 关键用户流程(点击路径)
- 组件规范(可复用的设计 token)

### 2. 用户审查与反馈

用户会进行以下操作之一:
- ✅ **批准**:"看起来不错,可以开始编码"
- 🔄 **要求修改**:"这里需要调整...",然后提供具体修改意见
- 🎨 **直接在 Figma 修改**:用户自己编辑原型,通知 Agent 查看
- ❌ **拒绝**:"这个方向不对,重新设计"

### 3. 迭代调整(如需要)

如果用户要求修改:
1. 根据反馈调整 Figma 原型
2. 更新 Figma 链接(或使用同一链接的新版本)
3. 再次通知用户审查
4. 重复直到批准

**重要**:不要在用户批准前开始编码,哪怕"觉得已经差不多了"。

### 4. 获得批准后开始编码

用户明确批准后:
```markdown
用户: "批准了,可以开始写代码"

AI Agent 行动:
1. ✅ 记录批准时间到实施文档
2. ✅ 按照 Figma 原型编写代码(严格遵循设计)
3. ✅ 实现过程中发现设计问题 → 停下来,回到 Figma 调整,再次获批
4. ✅ 完成后截图对比:代码实现 vs Figma 原型(确保一致性)
```

### 5. 验证与交付

代码完成后:
- 本地运行截图 vs Figma 原型对比
- 检查所有交互状态是否实现
- 检查响应式布局是否正确
- 提交代码 + Figma 链接 + 对比截图

## 🎨 设计参考

### 全屏地图霸屏式设计

**参考**: [高德地图官网](https://gaode.com/)

**核心特征**:
- 地图占满 100vh(整个视口高度)
- 所有 UI 元素悬浮在地图之上
- 透明背景 + 毛玻璃效果(`backdrop-filter: blur(12px)`)
- 圆角 16px + 柔和阴影
- 动画:面板折叠/地图飞行/气泡弹出

**布局结构**:
```
┌─────────────────────────────────────────┐
│ [Logo]  [搜索框]      [主题] [用户] ← 顶部导航(透明)
│                                         │
│  ┌────────┐                             │
│  │ 左侧   │         地图区域              │
│  │ 面板   │       (100vh 全屏)           │
│  │(可折叠)│                              │
│  └────────┘                     ┌───────┐│
│                                 │ AI    ││
│                                 │ 助手  ││
│  [比例尺] [测距]                │(可拖) ││
│                                 └───────┘│
│                                [定位][缩放]
└─────────────────────────────────────────┘
```

**悬浮组件**:
1. **顶部导航栏**:
   - 高度:64px
   - 背景:rgba(255,255,255,0.9) + blur(12px)
   - 阴影:0 2px 8px rgba(0,0,0,0.08)
   - 内容:Logo / 搜索框 / 主题切换 / 地图引擎切换 / 用户头像

2. **左侧面板**:
   - 宽度:320px(展开)/ 48px(折叠)
   - 背景:rgba(255,255,255,0.95) + blur(12px)
   - 圆角:0 16px 16px 0
   - 内容:最近大厂 / 我的收藏 / 插件列表

3. **右侧 AI 助手**:
   - 初始状态:56×56px 圆形气泡(右下角)
   - 展开状态:360×600px 对话框(可拖拽)
   - 背景:rgba(255,255,255,0.98) + blur(12px)
   - 圆角:16px

4. **左下角地图工具**:
   - 背景:rgba(255,255,255,0.9)
   - 圆角:8px
   - 内容:比例尺 / 测距 / 图层切换 / POI 过滤器

5. **右下角功能按钮**:
   - 定位按钮:48×48px 圆形
   - 缩放按钮:48×48px 圆形(上下堆叠)
   - 背景:rgba(255,255,255,0.9)
   - 悬停:放大 1.05x + 阴影加深

### 颜色系统

参考 `design_sense` 指令:

**基础色**:
- 深色背景:#0F172A(slate-900)
- 文本:#F8FAFC(slate-50)
- 边框:#334155(slate-700)

**强调色**:
- 主要动作:#38BDF8(sky-400)- 搜索/确认按钮
- 次要动作:#F97316(orange-500)- 高亮/推荐标记
- 成功:#10B981(green-500)
- 警告:#F59E0B(amber-500)
- 错误:#EF4444(red-500)

**地图标记色**(POI 图标):
- 招聘插件(公司):#3B82F6(蓝色)
- 租房插件(房源):#10B981(绿色)
- 院校插件(大学):#8B5CF6(紫色)
- 用户推荐(高亮):#F97316(橙色)

### 字体系统

- **无衬线字体**(界面):`Inter, 'Noto Sans SC', sans-serif`
- **等宽字体**(数据/代码):`'IBM Plex Mono', 'Courier New', monospace`

**字号**:
- Heading 1:32px / 2rem(页面标题)
- Heading 2:24px / 1.5rem(区块标题)
- Body:16px / 1rem(正文)
- Caption:14px / 0.875rem(说明文字)
- Tiny:12px / 0.75rem(标签/徽章)

### 组件规范

**按钮**:
- 主要按钮:蓝色填充 + 白色文字 + 圆角 8px + 悬停放大 1.02x
- 次要按钮:透明背景 + 蓝色边框 + 蓝色文字
- 图标按钮:48×48px 圆形 + 透明背景 + 悬停灰色背景

**卡片**(POI 详情卡片):
- 背景:白色(浅色模式)/ #1E293B(深色模式)
- 圆角:12px
- 阴影:0 4px 12px rgba(0,0,0,0.12)
- 内边距:16px
- 悬停:阴影加深 + 轻微上移(-2px)

**输入框**:
- 高度:48px
- 圆角:8px
- 边框:1px solid #E2E8F0
- 聚焦:边框变蓝色 + 外发光

**标签**(Tag/Badge):
- 高度:24px
- 圆角:12px
- 内边距:8px 12px
- 字号:12px
- 背景:浅色主题色(如蓝色标签 → bg-blue-100 + text-blue-700)

### ADR 中记录设计决策

重大 UI/UX 决策需记录到 `DOCS/06-decisions.md`:

```markdown
## ADR-005: 采用全屏地图霸屏式设计

**日期**: 2026-08-16
**状态**: ✅ 已批准
**决策者**: 用户 + AI Agent

### 背景
需要为 Domain Map Platform 选择首页设计方向。

### 决策
采用全屏地图霸屏式设计,参考高德官网(https://gaode.com/)。

### 理由
1. **沉浸式体验**:地图是核心功能,应占据最大视觉空间
2. **符合产品定位**:地图 POI 平台,而非传统 SaaS Dashboard
3. **差异化竞争**:与招聘网站的列表式设计形成区别
4. **空间利用**:悬浮组件不占用地图空间,用户可专注浏览

### 替代方案
- 传统三栏布局(左侧列表 + 中间地图 + 右侧详情)→ 被拒,地图空间太小
- 列表为主 + 小地图(如智联招聘)→ 被拒,地图沦为配角

### 后果
- **正面**:视觉冲击力强,用户体验独特,空间利用率高
- **负面**:移动端适配复杂(小屏幕悬浮组件会挤占地图)
- **缓解**:移动端采用抽屉式设计,组件默认隐藏,点击展开

### Figma 原型
https://www.figma.com/file/xxx/Domain-Map-Homepage-v3
```

## 🚫 常见错误

### ❌ 错误做法

**案例 1:直接写代码**
```markdown
AI Agent: "我先快速实现一个 MVP,然后再调整样式"
→ ❌ 错误!必须先 Figma 原型
```

**案例 2:口头描述代替设计**
```markdown
AI Agent: "我计划做一个蓝色导航栏,左边 Logo 右边搜索框,可以吗?"
→ ❌ 错误!必须可视化 Figma 原型,不能口头描述
```

**案例 3:未经批准就开始编码**
```markdown
AI Agent: "我已经把 Figma 发给你了,我先开始写基础结构..."
→ ❌ 错误!必须等待明确批准
```

**案例 4:自行决定"小调整"不需要 Figma**
```markdown
AI Agent: "这只是把按钮从 48px 改成 52px,不需要 Figma 吧?"
→ ❌ 错误!任何 UI 变更都需要 Figma
```

### ✅ 正确做法

**案例 1:创建原型 → 等待批准**
```markdown
AI Agent: 
"我已创建招聘地图主界面的 Figma 原型:
https://www.figma.com/file/xxx/Domain-Map-Homepage

设计要点:
- 全屏地图(100vh)
- 顶部透明导航栏
- 左侧可折叠面板(320px)
- 右侧 AI 助手气泡

请审查,批准后我将开始编码。"

[暂停,等待用户反馈]
```

**案例 2:收到修改意见 → 更新原型**
```markdown
用户: "左侧面板太宽了,改成 280px"

AI Agent:
"收到,我已将左侧面板宽度调整为 280px。
Figma 已更新(同一链接,v2 版本)。
请再次审查。"

[暂停,等待再次批准]
```

**案例 3:获得批准 → 开始编码**
```markdown
用户: "看起来不错,可以开始写代码了"

AI Agent:
"收到批准,开始编码。我会严格按照 Figma 原型实现。
预计完成时间:2 小时。"

[开始编写代码]
```

## 📊 检查清单

### 开发前检查(AI Agent)

在写前端代码前,确认:
- [ ] 我创建了 Figma 原型吗?
- [ ] 原型是否包含所有页面/组件/状态?
- [ ] 我已将 Figma 链接发给用户了吗?
- [ ] 用户明确批准了吗?(不是"看起来还行",而是"批准了,可以开始")
- [ ] Figma 链接已记录到实施文档中了吗?

如果任何一项为"否",**不要写代码**。

### 编码中检查

- [ ] 我的代码实现是否与 Figma 原型 100% 一致?
- [ ] 颜色/字体/间距/圆角是否严格遵循设计?
- [ ] 交互状态(hover/active/disabled)是否都实现了?
- [ ] 响应式布局是否与 Figma 的移动端设计一致?

### 完成后检查

- [ ] 截图对比:代码实现 vs Figma 原型
- [ ] 所有页面/组件都截图了吗?
- [ ] 发现任何不一致之处了吗?→ 修复后再提交
- [ ] Figma 链接 + 对比截图已附加到 PR 中了吗?

## 🎯 总结

**这条规则的目的**:
1. **避免返工**:设计错了改代码成本高,Figma 改设计成本低
2. **用户主导**:确保最终产品符合用户预期,而不是 AI 的猜测
3. **提升质量**:强制设计思考,而非"边写边想"
4. **沟通高效**:可视化设计比文字描述清晰 100 倍

**记住**:
> 💡 Figma 5 分钟,编码 2 小时。如果方向错了,Figma 白画 5 分钟;代码白写 2 小时。
> 
> 所以:**先 Figma,后代码**。永远。
